# 교통약자 지하철 접근성 GIS — 기능 정의

정리한 60여 개 데이터셋을 **3개 공간 스케일**로 쌓아 하나의 GIS로 묶는다.
스케일이 바뀌면 공간 데이터 모델도 바뀐다. 이 세 층을 하나의 좌표계에서 겹치는 것 자체가 이 프로젝트가 GIS인 이유다.

| 스케일 | 범위 | 데이터 모델 | 해상도 | 기능 |
| --- | --- | --- | --- | --- |
| S1 도시 — 역 밖 | 역 중심 1.5km | Raster (연속면) | DEM 5m 셀 | A1–A4 |
| S2 네트워크 — 노선 | 1~9호선 전 구간 | Vector (그래프) | 역간 에지 · 30분 | B1–B4 |
| S3 실내 — 역사 내부 | 역사 1동 (다층) | Vector 3D + Raster | 도면 0.5m · 층별 | C1–C4 |

- 총 12개 기능 / 벡터 12 · 래스터 9 / GIS 연산 32종
- 원 문서 링크 56개 전수 검증 결과 **영구 사망 0건** — 데이터가 없어 못 만드는 기능은 없다
- 좌표계: 분석은 `EPSG:5179`(UTM-K) 투영좌표, 웹 표출만 `EPSG:4326 / 3857`

# S1 · 도시 스케일 — 래스터 분석이 주력

## A1. 배리어프리 접근 비용면 생성

`Raster 주` `Vector` `코어` `난이도 상`

**왜 GIS인가** — 「경사가 몇 도냐」는 점이 아니라 **면(field)**의 성질이다. 등고선 벡터를 연속 표면으로 보간하고, 3×3 이웃 연산으로 경사를 뽑고, 지도대수로 여러 표면을 합치는 것은 래스터 GIS 말고 대체 수단이 없다.

**검증으로 확정된 사항** — 「서울시 경사도」 데이터셋은 완성된 경사도 래스터를 주지 않는다. 원문: *"요청한 경사도 shp은 없고, 경사도를 추출할 수 있는 표고점, 등고선 shp파일 제공입니다."* 따라서 DEM 직접 생성이 **선택이 아니라 필수 공정**이며, 래스터 GIS를 썼다는 증명이 자동으로 따라온다.

**입력 데이터**

- 서울시 경사도 — 등고선 + 표고점 shp (래스터 아님, 직접 보간 필요)
- 자치구별 도보 네트워크
- 횡단보도 위치정보
- 보행신호 음성안내 보조장치
- 역사 운영현황 (출입구 수)

**GIS 연산**

- `R` 등고선 LineString(z) → TIN / IDW / Spline 보간 → **DEM 래스터**
- `R` Horn 알고리즘 **경사 계산** (focal 3×3 이웃 연산)
- `R` **재분류** — 휠체어 기준 1/18(5.6%) 양호 · 1/12(8.3%) 한계 · 초과 통행불가
- `R` 횡단보도·음성유도기 → **커널밀도추정(KDE)** 래스터
- `R` **지도대수 가중중첩** — AHP로 경사·횡단시설·보도폭 가중치 결정
- `R` 출입구 Point를 소스로 **비용거리(cost-distance)** + **최소비용경로(LCP)**
- `R` 행정동 폴리곤별 **존 통계(zonal statistics)**
- `V` 좌표계 통일 `EPSG:5174/5186 → 5179`

**산출물** — 5m 해상도 「휠체어 통행비용」 GeoTIFF, 역별 접근 가능 면적, 지도 위 반투명 래스터 오버레이

## A2. 실측 도보 등시선과 역세권 재정의

`Vector 주` `Raster` `코어` `난이도 상`

**왜 GIS인가** — 「반경 500m 역세권」은 지도 위의 원일 뿐이다. 실제 보도를 따라 걷고 경사에 따라 느려지는 **네트워크 임피던스**로 도달범위를 다시 그리면, 원과 등시선의 **차집합**이 곧 "지도상 역세권인데 휠체어로는 못 가는 땅"이 된다. 이 프로젝트의 핵심 메시지.

**입력 데이터**

- 자치구별 도보 네트워크 *(서울 데이터 허브로 이전, 로그인 없이 다운로드 가능)*
- 횡단보도 위치정보
- A1 경사 래스터
- KRiC 출입구 위치
- 등록장애인 동별 통계

**GIS 연산**

- `V` **위상 구축** — noding · snapping · planarize, 끊긴 링크 자동 탐지
- `V` 횡단보도 Point ↔ 보도 링크 **컨플레이션**, 미연결 지점 = 보행 단절
- `R` 링크 양단에서 **래스터 점 샘플링**으로 표고 추출 → 링크별 경사 부여
- `V` **경사 보정 임피던스** — Tobler 보행함수의 휠체어 변형
- `V` **네트워크 서비스영역** 5 · 10 · 15분 등시선
- `V` 도달 노드 → **알파 셰이프(concave hull)**로 폴리곤화
- `V` 유클리드 버퍼 500m 와 **오버레이 차집합(difference)**
- `V` 동별 장애인 통계 → **면적가중 내삽 / dasymetric mapping**

**산출물** — 역별 등시선 폴리곤(GeoJSON), "허수 역세권" 면적 지표, 영향 인구 추정치

## A3. 편의시설 결핍 지도 — 수요·공급 불일치

`Raster` `Vector` `확장` `난이도 중상`

**왜 GIS인가** — 시설이 **어디에 얼마나 몰려 있는가**(공급면)와 **누가 어디서 쓰는가**(수요면)를 각각 연속 표면으로 만든 뒤 빼면, 우선 설치 후보지가 셀 단위로 떨어진다. 보건지리학 표준 지표 2SFCA를 그대로 적용할 수 있는 구조.

**입력 데이터**

- 장애인 화장실 · 음성유도기 · 수어 영상전화기 · 교통약자 도우미
- 휠체어 급속충전기 (서울 + 전국 공공데이터 `_20260213` 최신본)
- 노인 · 장애인 시간대별 승하차
- 등록장애인 통계 · 생활인구

**GIS 연산**

- `R` 시설 Point → **KDE 공급 래스터** (대역폭 = 도보 5분 거리)
- `V` **티센 폴리곤(Voronoi)** 또는 A2 등시선으로 역 캐치먼트 정의
- `V` 교통약자 승하차 → 캐치먼트 **면적가중 배분** → 수요 래스터
- `R` 정규화 후 **지도대수 차분** `supply − demand`
- `R` **2SFCA** 2단계 부동 캐치먼트 접근성 지수
- `R` 상위 결핍 셀 → **래스터→벡터 변환(polygonize)**

**산출물** — 시설 유형별 gap 래스터, 우선 설치 후보 구역 리스트

## A4. 행정동 접근성 대시보드와 이동 흐름

`Vector` `Raster` `확장` `난이도 중`

**왜 GIS인가** — 셀 단위 결과를 **행정 단위로 집계**해야 정책 언어가 된다. 존 통계·이변량 코로플레스·공간회귀는 전부 "공간 자체가 변수인" 통계라 일반 BI 대시보드로는 나오지 않는다.

> ⚠️ **설계 변경 필요** — 「연령·목적별 생활이동」과 「교통수단별 생활이동」은 그런 구분이 아니다. 실제로는 `OA-22299` = 수도권 생활이동 **내국인**(연령별·출발도착지), `OA-22656` = 수도권 생활이동 **외국인**(시간대·성연령·수단)으로 **내국인/외국인 분할**이다. 교통수단별 비교를 하면 외국인 데이터를 쓰게 된다.

**입력 데이터**

- A1 접근 비용 래스터
- 등록장애인 성별·연령별·동별
- 서울 생활인구 (집계구 단위)
- 수도권 생활이동 내국인 / 외국인
- 시간대별 역·정류장 OD

**GIS 연산**

- `R` **존 통계** — 접근 비용 래스터 × 행정동 폴리곤 (평균 · 최댓값 · 면적비)
- `V` **공간 조인 + 집계**, 정규화 후 코로플레스
- `V` **이변량 코로플레스** — 수요(장애인 밀도) × 접근성 → 4분면 우선순위
- `V` OD → **플로우 맵** (베지어 아크 + 흐름 집계)
- `V` **지리가중회귀(GWR)** — 접근성이 이용량에 미치는 영향의 지역적 이질성

**산출물** — 자치구·행정동 스코어카드, OD 플로우 맵, GWR 계수 지도

# S2 · 네트워크 스케일 — 시간이 붙은 공간 그래프

## B1. 교통약자 다기준 경로탐색 엔진

`Vector` `코어` `난이도 상`

**왜 GIS인가** — 일반 길찾기와 다른 점은 **비용함수**다. 「빠른 길」 대신 「환승 계단이 없는 길」, 「연단 간격이 좁은 길」을 계산하려면 공간 그래프의 에지마다 접근성 속성을 붙여야 한다. 좌표를 가진 노드·에지 위에서 도는 최단경로 = 네트워크 GIS.

**입력 데이터**

- 덤프: `station_master` · `subway_edge` · `edge_direction` · `edge_time` · `timetable_departure`
- 환승역 거리·소요시간
- 사용자유형별 환승 승객수·환승시간 (일반/경로/장애인)
- 1~9호선 혼잡도
- 연단정보와 곡선구간 정보, 차량별 휠체어석 탑승 위치

**GIS 연산**

- `V` Point / LineString 기반 **네트워크 위상 생성** (pgRouting `createTopology`)
- `V` **시간의존 최단경로** — time-dependent Dijkstra 또는 RAPTOR
- `V` **턴 / 환승 페널티** — 장애인 실측 환승시간을 turn restriction 비용으로 삽입
- `V` **다기준 파레토 최적 경로** — 시간·환승수·수직이동·혼잡·연단위험 동시 최적화 → "빠른 길 / 편한 길 / 안전한 길" 3안
- `V` 결과 경로에 **선형참조(M값)**로 구간별 소요시간 라벨링
- `V` **공간 인덱스(GiST)** + `ST_DWithin` 최근접 역 탐색

**산출물** — 경로 GeoJSON LineString, 구간별 부담 프로파일, "이 경로엔 계단 2곳" 경고

## B2. 혼잡도 시공간 큐브

`Vector` `Raster` `확장` `난이도 중상`

**왜 GIS인가** — 혼잡도는 (x, y, t) 3차원 격자다. 시간축을 가진 **3D 래스터(space-time cube)**로 쌓으면 "지속적으로 붐비는 역"과 "점점 나빠지는 역"을 통계적으로 구분할 수 있다. 공간적 자기상관 검정은 GIS 고유의 통계.

**입력 데이터**

- 서울교통공사 1~8호선 혼잡도 (30분 단위) · 9호선 혼잡도
- 호선·역·시간대별 승하차, 일별 역별 승하차
- 승객유형별 · 노인 · 장애인 승하차

**GIS 연산**

- `R` 역 Point × 30분 bin → **시공간 큐브 (x, y, t 3D 래스터)**
- `R` **시공간 보간** IDW / Kriging → 노선 축을 따르는 연속 혼잡 표면
- `V` **Getis-Ord Gi 핫스팟** + **Mann-Kendall 추세** → 지속과밀 / 심화중 / 완화중
- `V` **Local Moran's I (LISA)** — 주변과 다른 이상치 역 탐지
- `V` 노선 LineString에 **선형참조**로 혼잡 구간 이벤트 매핑
- `R` 타임슬라이더용 **XYZ / COG 래스터 타일** 서빙

**산출물** — 타임슬라이더 혼잡 히트맵, 핫스팟 분류 지도, 교통약자 회피시간대 추천

## B3. 엘리베이터 장애 파급영향 시뮬레이터

`Vector` `Raster` `코어` `난이도 상`

**왜 GIS인가** — 엘리베이터 하나가 멈추면 그 역은 휠체어 이용자에게 **지도에서 사라진다**. 그래프에서 에지를 지우고 연결성을 재검사한 뒤 등시선을 다시 그려 **차집합 면적**을 재면, "오늘 이 고장으로 잘려나간 도시 면적"이 숫자로 나온다. 시연 임팩트가 가장 큰 기능.

**입력 데이터**

- 승강기 가동현황 (실시간), 엘리베이터 위치·운영정보
- 출입구 임시폐쇄 현황, 역사 내 공사현황
- C2 실내 3D 네트워크
- A2 도보 등시선

**GIS 연산**

- `V` 실시간 상태 → **동적 그래프 편집** (해당 수직 에지 비용 = ∞)
- `V` **연결성 분석(connected components)** — 출입구↔승강장 휠체어 경로 존재 여부
- `V` 해당 역 제거 후 노선 그래프 **재라우팅** + **최근접 시설(closest facility)**로 대체역 탐색
- `V` 등시선 재계산 → 정상시 폴리곤과 **차집합** → 손실 면적 · 손실 인구
- `R` 일별 결과를 **래스터 스택 시계열**로 누적 → 연간 「접근불가 시간」 래스터

**산출물** — 실시간 "오늘 못 가는 역" 지도, 손실 면적 km² · 영향 인구, 연간 누적 취약지도

## B4. 실시간 운행·이용제한 통합 상황판

`Vector` `확장` `난이도 중`

**왜 GIS인가** — 열차 좌표를 그냥 찍으면 선로를 벗어난다. **맵 매칭**으로 노선 라인에 붙이고 **선형참조**로 구간 진행률을 계산해야 "지금 어디쯤"이 정확해진다.

**입력 데이터**

- T-DATA 실시간 열차 위치·도착정보 *(서버 불안정 — 재시도 로직 필수)*
- 지하철 알림정보 (비정형 텍스트)
- 역별 지연시간 이력, 열차 운행시각표 (`_20260616` 최신본)
- 최단경로 이동정보 (검증용 baseline)

**GIS 연산**

- `V` **맵 매칭** — 열차 좌표를 노선 LineString에 투영 (`ST_ClosestPoint`)
- `V` **선형참조** `ST_LineLocatePoint` → 역간 진행률 0~1
- `V` 비정형 알림 → LLM 구조화 → **지오코딩**(역명 → 좌표) → 지도 배지
- `V` **벡터 타일(MVT)** 실시간 갱신 + WebSocket 푸시
- `V` 지연 이력 → 역별 **지연 위험도** 속성으로 B1 경로비용에 환류

**산출물** — 실시간 열차 위치 지도, 역별 이용제한 배지, B1 경로 재계산 트리거

# S3 · 실내 스케일 — 없는 데이터를 만들어 쓰는 층

> **"역사 내부를 그릴 수 있는 shp 파일이 없다"** 가 여기서 풀린다.
> 해법은 역 이용안내도 이미지를 **지오레퍼런싱**해 직접 실내 벡터를 디지타이징하는 것.
> 전 역을 다 할 필요는 없고 **환승 대역 5~10개 역**만 해도 시연으로 충분하며,
> "데이터를 직접 생산했다"는 점이 평가에서 가장 강한 카드가 된다.

## C1. 역사 안내도 지오레퍼런싱 파이프라인

`Raster 전용` `코어` `난이도 중상`

**왜 GIS인가** — 이미지에 좌표를 부여하는 **지오레퍼런싱**은 래스터 GIS의 정의 그 자체다. 좌표 없는 PNG를 GCP로 실세계에 맞추고 RMSE로 정확도를 보고하는 과정이 있으면, "래스터 기능을 썼다"는 주장이 가장 확실하게 증명된다.

**입력 데이터**

- 서울교통공사 역 이용안내도 (층별 이미지)
- 역사 면적정보 · 역사 건축정보 (길이·형태)
- 엘리베이터·에스컬레이터 위치 (GCP 후보)
- KRiC 출입구 좌표 (GCP 후보)

**GIS 연산**

- `R` **GCP(지상기준점) 설정** — 출입구·EV 실좌표 ↔ 이미지 픽셀좌표 4~8쌍
- `R` **기하보정 변환** — Affine / 2차 다항식 / Thin-plate spline, **RMSE**로 채택 판정
- `R` **리샘플링** (nearest / bilinear) + **월드파일(.pgw) · GeoTIFF** 출력
- `R` **마스킹 / 클리핑**으로 도면 외곽 여백 제거, 알파 채널 부여
- `R` **COG + 타일 피라미드** 생성 → 웹 오버레이 (TiTiler)
- `R` 층별 **래스터 스택** 구성 (B1F · B2F · …) 및 층 전환 UI

**산출물** — 좌표가 박힌 층별 역사 도면 GeoTIFF, 지도 위 정합 오버레이, C2의 디지타이징 배경

## C2. 실내 3D 다층 네트워크 라우팅

`Vector 3D` `Raster` `코어` `난이도 최상`

**왜 GIS인가** — 건물 안은 층이 있어서 2D 그래프로는 못 푼다. 층을 속성으로 갖는 노드와 **수직 전이 에지**(EV·ES·계단)로 이뤄진 **IndoorGML식 node-relation graph**가 필요하고, 계단 비용을 ∞로 두는 순간 휠체어 전용 경로가 나온다.

**입력 데이터**

- KRiC 교통약자 이동동선 API — 환승 이동경로, 출입구→승강장 경로, 엘리베이터 동선
- 엘리베이터 · 에스컬레이터 · 휠체어리프트 · 무빙워크 위치
- **역사 EV·ES 길이·높이 정보** (2026-04 갱신) — 수직 비용을 추정이 아닌 **실측**으로
- 휠체어경사로 설치 현황 — 실내 경사로 에지
- 역사 심도정보, 역사 운영현황 (층수·승강장 형식·출입구 수)
- 지하철 연결통로 시설물정보
- C1 지오레퍼런싱된 층별 도면

**GIS 연산**

- `R` 정합된 도면 위 **온스크린 디지타이징** → 실내 통로 LineString · 노드 Point 생성
- `V` **3D 위상 구축** — `level` 속성 + 층간 전이 에지, IndoorGML node-relation graph
- `V` 심도(m)를 **수직 이동 비용**으로 환산 (EV 대기시간 + 층당 이동시간)
- `V` **제약 최단경로** Dijkstra / A-star — 계단 = ∞, EV 고장 시 동적 차단 (B3 연동)
- `V` 출입구 → 개찰구 → 승강장 → 환승통로 **구간 분해** 후 층별 렌더링
- `V` 결과를 **3D LineString (Z 좌표 포함)** GeoJSON으로 반환

**산출물** — "출입구 3번 → EV → B2 승강장" 단계별 실내 경로, 층 전환 애니메이션, 총 수직이동 높이

## C3. 승강장 연단간격 선형참조 위험도

`Vector` `코어급` `난이도 중상`

**왜 GIS인가** — 승강장은 **선형 객체**다. 칸·문 번호를 M값으로 두고 간격·높이차를 **선형 이벤트**로 붙이면, 동적 분할로 "이 승강장의 이 구간이 위험"을 색으로 칠할 수 있다. 도로 GIS의 dynamic segmentation을 승강장에 옮긴 것 — 아이디어 독창성이 가장 높다.

**등급 상향** — KRiC에 「인접 승강기 차량번호」·「인접 계단 차량번호」가 존재한다. "몇 번째 칸이 승강기와 가까운가"가 M값 이벤트로 그대로 꽂히므로, 확장이 아니라 코어급이다.

**입력 데이터**

- 연단정보와 곡선구간 정보 (간격·높이차)
- 안전발판 보유현황, 이동식 안전발판 설치 위치
- 차량별 자전거거치대 및 휠체어석 탑승 위치
- KRiC `stationElevatorCarNumber` — 인접 승강기 차량번호
- KRiC `stationStairCarNumber` — 인접 계단 차량번호
- KRiC `stationPlatformTrainDistance` — 승강장 이격거리 (+plfNo)
- 역사 운영현황 (승강장 형식: 상대식 / 섬식)

**GIS 연산**

- `V` 승강장을 **LineString(M)**으로 모델링, 칸·도어 번호를 **측정값(measure)**으로 부여
- `V` 간격·높이차 이벤트 테이블 → **동적 분할(dynamic segmentation)**로 구간 색상화
- `V` 안전발판 Point → `ST_LineLocatePoint` **최근접 이벤트 스냅**
- `V` 곡선구간 **기하 곡률 계산** → 위험 등급 (직선 / 완곡 / 급곡)
- `V` 휠체어석 탑승 위치 ↔ C2 실내 경로 **네트워크 조인** → "3-2 문으로 타세요"

**산출물** — 승강장 위험구간 스트립 지도, 탑승 문 번호 추천, 발판 요청 필요 여부

## C4. 역사 심도 3D 단면 뷰

`Vector 3D` `Raster` `확장` `난이도 중`

**왜 GIS인가** — 「지하 6층」이 얼마나 부담인지는 숫자보다 단면이 설득력 있다. 지표 DEM 아래로 역사를 **익스트루전**해 배치하면 지형 기복까지 반영된 실제 하강 깊이가 보인다. 2D 길이가 아니라 **3D 길이**를 재는 게 포인트.

**입력 데이터**

- 역사 심도정보 (승강장 깊이)
- 역사 면적정보 · 역사 건축정보 (준공연도·형태)
- EV · ES 위치 및 운영정보
- **역사 EV·ES 길이·높이 정보** — 단면의 Z축을 실측값으로 채운다
- A1 DEM 래스터 (지표면)

**GIS 연산**

- `R` DEM에서 역사 위치 **표고 샘플링** → 지표 기준면 산정
- `V` 면적 폴리곤 + 심도 → **3D 익스트루전** (deck.gl / CesiumJS)
- `V` 경로별 **3D 길이 vs 2D 길이** 비교 → 누적 수직 이동량 지표
- `V` 수직시설 위치를 Z축에 배치해 **단면 프로파일** 렌더링

**산출물** — 역별 3D 단면 카드, "지상 → 승강장 총 하강 27m" 같은 체감 지표

# 우선순위

## 최소 시연 조합 (6개)

**A1 + A2 + B1 + B3 + C1 + C2**

이 여섯이면 *"래스터 지형분석 → 벡터 네트워크 → 실내 3D → 실시간 반영"* 이라는 서사가 완결된다. 나머지 여섯은 시간이 남을 때 붙이는 확장.

## 난이도 순

| 난이도 | 기능 |
| --- | --- |
| 최상 | C2 |
| 상 | A1 · A2 · B1 · B3 |
| 중상 | A3 · B2 · C1 · C3 |
| 중 | A4 · B4 · C4 |

## 착수 전 결정사항

- **좌표계를 먼저 못 박을 것.** 서울시 데이터는 `EPSG:5174`(중부원점 구) · `5179`(UTM-K) · `5186`이 섞여 들어온다. 면적·거리·경사 연산은 반드시 투영좌표(5179)에서, 웹 표출만 `4326 / 3857`로. 나중에 고치면 A1·A2 결과가 통째로 어긋난다.
- **역 코드 매핑 테이블부터 만들 것.** KRiC의 `stinCd`와 서울시 데이터의 `stnCd` / `stop_id` 체계가 다르다. 덤프의 `station_master`를 기준 테이블로 삼아 매핑을 먼저 확정해야 S2·S3가 연결된다.
- **혼잡도 출처를 하나로 통일할 것.** 서울 공공 혼잡도와 SK Open API는 측정 기준이 다를 수 있다. 하나를 택하고 출처를 명시한다.
