# 개발 가능한 기능 목록

12개 전부 어떤 형태로든 개발 가능하다. 다만 **착수 조건**이 다르다.
아래는 조건이 가벼운 순서다. 위에서부터 그냥 시작하면 된다.

---

## 1군 — 지금 바로 시작 가능 (파일 다운로드만 하면 끝)

외부 승인도, 확인해야 할 것도 없다.

### A1. 배리어프리 접근 비용면
등고선·표고점으로 DEM을 만들어 휠체어 통행 부담을 5m 셀로 칠한다.
- 데이터: 서울시 경사도(`OA-22241`, 등고선+표고점 shp) · 횡단보도(`OA-21209`) · 음성유도기(`OA-22218`)
- 연산: TIN/IDW 보간 → Horn 경사 → 재분류 → KDE → 지도대수 가중중첩 → 비용거리/LCP → 존통계
- 조정 1: AHP 인자에서 **「보도폭」을 뺀다** (그 데이터가 없다). `경사 · 횡단보도 밀도 · 육교/지하보도 밀도`로 교체
- 조정 2: 산출물 라벨은 "지형 기복에 따른 통행 부담". 연석·단차는 5m DEM에 안 잡힌다

### A2. 실측 도보 등시선 · 역세권 재정의
반경 500m 원과 실제 보행 등시선의 차집합 = "지도상 역세권인데 휠체어로는 못 가는 땅".
- 데이터: 도보 네트워크(`OA-21208`, 노드/링크 위상 있음) · 횡단보도 · A1 경사 래스터 · 등록장애인 동별 통계
- 연산: 위상 구축 → 링크별 DEM 샘플링 → 경사 임피던스 → 서비스영역 등시선 → 알파셰이프 → 버퍼 차집합 → dasymetric
- 조정: **계단 속성이 없다.** 링크 평균 경사 15% 초과를 계단 대리변수로 처리하고, 그 사실을 문서·발표에 명시

### A4. 행정동 접근성 대시보드
셀 단위 결과를 행정동으로 집계해 정책 언어로 바꾼다.
- 데이터: A1 래스터 · 등록장애인 통계 · 생활인구 · 생활이동(`OA-22299` 내국인) · OD(`OA-21222`)
- 연산: 존통계 → 공간조인 집계 → 이변량 코로플레스 → 플로우맵 → GWR (행정동 424개, 표본 충분)
- 주의: `OA-22656`은 **외국인** 데이터다. 수단별 분석을 하면 외국인을 쓰게 된다

### C4. 역사 3D 단면
"지상에서 승강장까지 27m 하강" 을 단면으로 보여준다.
- 데이터: 역사 심도(`OA-13305`) · 면적(`OA-22448`) · 건축정보(`OA-11572`) · **EV/ES 길이·높이(`OA-12514`)** · A1 DEM
- 연산: DEM 표고 샘플링 → 3D 익스트루전 → 3D 길이 vs 2D 길이 → 단면 프로파일
- 리스크 없음. 난이도도 낮다

### B1. 다기준 경로탐색 (4기준 버전)
시간 · 환승수 · 혼잡 · 연단위험 4개 기준으로 파레토 경로 3안을 낸다.
- 데이터: dump(`station_master`·`subway_edge`·`edge_time`·`timetable`) · 환승역 거리/소요시간(`OA-13290`) · 사용자유형별 환승시간(`OA-21221`) · 혼잡도(`OA-12928`) · 연단정보(`OA-22124`)
- 연산: 네트워크 위상 → 시간의존 Dijkstra/RAPTOR → 턴·환승 페널티 → 다기준 파레토 → 선형참조 라벨링
- 「계단 없는 길」 기준 하나만 KRiC 키가 필요하다. **나머지 4기준은 키 없이 완성된다**

## 2군 — 명세만 고치면 바로 가능

데이터는 다 있는데 명세에 적힌 방법이 데이터 성격과 안 맞는다.

### A3. 편의시설 결핍 지도
- **고칠 것**: 시설 KDE 연속 공급면 → **역 단위 2SFCA**
  (장애인화장실·수어전화기·도우미·충전기는 대부분 역사 내부 시설이라 KDE를 돌리면 "역 위치의 KDE"가 된다)
- 가로에 흩어진 시설(음성유도기·횡단보도)만 KDE로 따로 다룬다
- 데이터: 시설 5종 · 노인/장애인 승하차 · 등록장애인 · 생활인구 · A2 등시선(캐치먼트)

### B2. 혼잡도 분석
- **고칠 것**: (x,y,t) 3D 크리깅 큐브를 뺀다. 역이 노선 축 위 1차원 사슬이라 보간해도 정보가 안 늘어난다
- **고칠 것**: 핫스팟 가중치를 유클리드 → **네트워크 인접**으로
- **전제**: 추세 분석(Mann-Kendall)을 하려면 혼잡도 **연도별 파일을 여러 개** 받아야 한다.
  단일 파일은 요일·방향별 30분 평균(대표일)이라 날짜축이 없다
- 축소판: 역 단위 시간대 프로파일 + 네트워크 가중 Getis-Ord 핫스팟 → 이것만으로 충분히 성립

### B4. 실시간 상황판
- **고칠 것**: 맵매칭(`ST_ClosestPoint`)을 뺀다. 실시간 열차 API는 `statnId`/`trainSttus`만 주고 **좌표가 없다**
- 대체: 역 이벤트 → 노선 선형참조 보간 (현재역 M값~다음역 M값 사이를 상태코드로 배분). 선형참조 연산은 그대로 유지된다
- 알림정보(`OA-22718`)는 형식이 없어 파싱이 어렵다. LLM 구조화는 **데모 보조**로만, 정량 지표에는 넣지 말 것

### C1. 안내도 지오레퍼런싱 (시각화 전용)
- **고칠 것**: 산출물을 "실내 벡터 생산의 기반" → **"지도 위 정합 오버레이 + RMSE 정직 보고"**
- 역이용안내도(`OA-11984`)는 모식도일 가능성이 높다. 모식도면 RMSE가 크게 나오는데,
  그걸 그대로 보고하는 것이 방법론적으로 정직한 결과다
- GCP는 `OA-21212`(지하철역 엘리베이터 위치정보, **WGS84 좌표**)와 출입구 좌표로 확보
- **C2가 이 도면 위에서 거리를 재지 않도록 분리한다** (아래 C2 참조)

## 3군 — 파일 1개만 열어보면 확정 (게이트 통과 후 가능)

### B3. 엘리베이터 장애 파급영향
- **게이트**: 승강기 가동현황(`OA-15994`) 갱신주기가 실시간인가 스냅샷인가
  - 실시간 → "오늘 ○○역 EV 정지로 1.4km² 사라짐"
  - 스냅샷 → **what-if 시뮬레이터**로 프레이밍 변경. 데모 임팩트는 거의 그대로다
- 데이터: `OA-15994` · 출입구 임시폐쇄(`OA-22122`) · 역사 내 공사현황(`OA-22751`) · A2 등시선
- 연산: 동적 그래프 편집 → 연결성 분석 → 재라우팅 → 등시선 차집합 → 래스터 스택 누적
- 주의: 손실 면적이 A2 등시선에서 나오므로 **A2의 계단 부재 오차를 그대로 상속한다.** 발표에서 명시할 것

### C3. 연단간격 선형참조 위험도
- **게이트**: `OA-22124`의 「승강장위치」 컬럼 값이 `1-1`/`3-4` 같은 차량-도어 번호인가
  - 차량-도어 번호 → M값 이벤트가 그대로 꽂힌다. 동적 분할이 진짜로 작동한다
  - 역당 1행 대표값 → **역별 위험 등급표**로 축소 (그래도 성립은 한다)
- 데이터: `OA-22124`(호선·역외부코드·역코드·역명·상하선·승강장위치·연단간격·높이차) · 안전발판(`OA-22747`,`OA-22498`) · 휠체어석 탑승위치(`OA-22531`) · 역사 운영현황(`OA-22452`)
- 부수: **승강장 LineString(M) 기하는 주어지지 않는다.** 역 좌표 + 승강장 형식 + 역사 길이로 합성하고, 합성 기하임을 명시

## 4군 — KRiC 서비스키 승인 후 가능

### C2. 실내 3D 다층 라우팅
- **전제**: KRiC 서비스키. 19건 개별 신청이라 승인에 시간이 걸린다. **오늘 신청 시작할 것**
- **핵심**: KRiC은 좌표를 안 주지만 위상(`stMovePath`→`edMovePath`+순서) · 실거리(`mvDst`) · 층(`stinFlor`) · 승강기 유형/상태(`elvtTpCd`/`elvtSttCd`)를 준다.
  이건 node-relation graph 그 자체다 → **좌표 없이 계단=∞ 라우팅이 돈다**
- 수직비용은 `OA-12514`(EV/ES 길이·높이)로 추정이 아닌 실측
- C1 도면은 **표출 배경으로만** 쓴다. 안내도가 모식도로 판명나도 C2는 안 무너진다
- 신청 우선순위: `transferMovement` → `stinElevatorMovement` → `stationMovement` → `stationPlatformTrainDistance` → `stationElevatorCarNumber` → `stationStairCarNumber` → 나머지
