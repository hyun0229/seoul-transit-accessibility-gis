# 바로 착수 가능한 기능 5건

외부 승인도, 확인해야 할 것도 없다. 데이터만 내려받으면 오늘 시작할 수 있다.

## 기능 개요

| 기능 | 무엇을 하는가 | 화면에 나오는 것 |
| --- | --- | --- |
| **역사 3D 단면 뷰** | 지표 DEM에서 역 위치의 표고를 잡고, 그 아래로 역사를 심도만큼 익스트루전한다. 승강기 실측 길이·높이를 Z축에 배치해 수직 이동시설이 어느 층을 잇는지 단면에 그린다. 평면 길이가 아니라 **3D 길이**를 재는 게 핵심 | 역별 3D 단면 카드. "지상 → 승강장 총 하강 27m · 3D 이동거리 82m" — 평면도상 50m가 실제로는 82m |
| **배리어프리 접근 비용면** | 서울시는 완성된 경사도 지도를 주지 않고 등고선·표고점만 준다. 이걸 연속 표면(DEM)으로 보간하고, 3×3 이웃 연산으로 경사를 뽑아 휠체어 기준으로 재분류한다. 횡단보도·음성유도기 밀도를 얹어 지도대수로 합치면 셀마다 "지나가는 부담" 값이 생긴다 | 5m 해상도 통행비용 래스터가 지도 위에 반투명으로 깔린다. 붉은 구역 = "역이 코앞인데 지형 때문에 못 가는 땅". 역별 접근 가능 면적 |
| **실측 도보 등시선 — 역세권 재정의** | 반경 500m 역세권은 컴퍼스로 그린 원일 뿐이다. 도보 링크마다 DEM 경사를 붙여 임피던스를 매기고 5·10·15분 도달범위를 계산한 뒤, **500m 원에서 등시선을 뺀다** | 원과 등시선이 겹쳐 그려지고 그 사이 빗금이 **허수 역세권**. 동별 장애인 통계를 면적가중 내삽해 "이 구역에 장애인 몇 명이 산다"까지 |
| **교통약자 다기준 경로탐색** | 일반 길찾기와 다른 건 알고리즘이 아니라 **비용함수**다. 환승 에지에 장애인 실측 환승시간을 turn penalty로 넣는다 — 일반인 3분이 장애인 9분이면 경로 선택이 통째로 바뀐다. 시간·환승수·혼잡·연단위험을 동시에 최적화 | 서로 지배하지 않는 경로 3안: **빠른 길 / 편한 길 / 안전한 길**. 구간별 부담 프로파일 "환승 2회 · 12분 · 연단간격 최대 12cm 구간 있음" |
| **행정동 접근성 대시보드** | 비용면이 만드는 건 5m 셀 수십만 개다. 분석 결과지 의사결정 자료가 아니다. 행정동으로 존 집계해 점수로 바꾸고, 수요(장애인 밀도)를 한 축 더해 이변량 코로플레스를 그린다 | `수요 높음 × 접근성 나쁨` 4분면이 그대로 우선순위 목록. 자치구·행정동 스코어카드, OD 플로우 맵, GWR 계수 지도 |

## 착수 순서

의존 관계가 있어서 순서가 정해진다.

1. **역사 3D 단면 뷰** — 다른 기능에 의존하지 않고 가장 빨리 끝난다. 첫 성과물로 좋다
2. **배리어프리 접근 비용면** — DEM을 만든다. 이게 아래 두 개의 입력이 된다
3. **실측 도보 등시선** — 2의 경사 래스터가 필요하다
4. **행정동 대시보드** — 2의 비용 래스터가 필요하다
5. **다기준 경로탐색** — 위와 독립이므로 아무 때나. dump만 있으면 시작 가능

> 1과 5는 다른 기능과 독립이라 **병렬로 돌려도 된다.**

## 착수 전 공통 결정 3건

- **좌표계 고정** — 면적·거리·경사 연산은 투영좌표 `EPSG:5179`, 웹 표출만 `4326/3857`.
  서울시 데이터는 `5174 / 5179 / 5186`이 섞여 온다. 나중에 고치면 비용면과 등시선이 통째로 어긋난다.
- **역 코드 매핑 테이블 먼저** — `station_master` 기준, 조인 키는 **역명 + 호선**,
  역사마스터 위·경도로 교차검증. `OA-22124`가 역외부코드와 역코드를 함께 주므로 브릿지로 쓸 만하다.
- **혼잡도 출처 단일화** — 서울 공공 혼잡도와 SK Open API는 측정 기준이 다를 수 있다. 하나만 쓰고 출처를 명시한다.
