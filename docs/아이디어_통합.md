# 동료 아이디어 6건 ↔ 기존 기능 12건 대조

동료가 제시한 6건은 **전부 기존 명세와 겹친다.** 다만 겹치는 방식이 두 종류다.

- **완전 중복** — 같은 데이터로 같은 것을 만든다. 합치면 된다 (3건)
- **같은 데이터 · 다른 산출물** — 동료는 개인 이용자용 표출, 기존 안은 공간분석. 앞뒤로 붙는다 (3건)

---

## 대조표

| 동료 안 | 대응 기존 기능 | 겹침 | 차이 |
| --- | --- | --- | --- |
| **1. 계단 0% 환승 경로** | 다기준 경로탐색 + 실내 3D 라우팅 | **완전 중복** | 동료는 「계단 배제」 단일 기준, 기존 안은 시간·환승수·혼잡·연단위험까지 다기준 파레토 |
| **2. EV 위치 + 당일 점검현황** | EV 장애 파급영향 + 3D 단면 | 데이터 동일 | 동료는 **표출**(초록/빨강 핀), 기존 안은 **계산**(그 고장이 도시 면적 몇 km²를 잘라내는지) |
| **3. 연단간격 위험 + 휠체어석** | 연단간격 선형참조 위험도 | **완전 중복** | 동료가 UI를 더 구체화(10cm 임계, 도어별 1-1~8-4 다이어그램) |
| **4. 개찰구 밖 화장실·충전소** | 편의시설 결핍 지도 | 데이터 동일 | 동료는 **검색·필터**(개인용), 기존 안은 **결핍 분석**(정책용) |
| **5. 역세권 안심 보행로** | 실측 도보 등시선 + 접근 비용면 | 데이터 동일 | 동료는 **A→B 경로(선)**, 기존 안은 **도달범위(면)**. 같은 임피던스 그래프에서 나오는 두 산출물 |
| **6. 쾌적 승차 시간대 추천** | 혼잡도 핫스팟 | **완전 중복** | 동료는 1개 역의 시간축 추천, 기존 안은 전 노선 공간 핫스팟. 동료 안이 기존 안의 산출물 항목 하나 |

**임피던스 그래프를 한 번 만들면 동료 5와 기존 등시선이 둘 다 나온다.** 추가 비용이 거의 없다.

## 동료 안이 새로 가져온 것 — 흡수할 가치가 있는 5가지

기존 명세에 없던 관점이다. 그대로 받는다.

| # | 무엇 | 왜 좋은가 |
| --- | --- | --- |
| 1 | **개찰구 내/외 구분** (동료 4) | 카드를 태그하기 전에 쓸 수 있는 화장실인가 — 실사용에서 결정적인데 기존 명세에 없었다. `서울교통공사 장애인 공중화장실`이 **개찰구 내·외부·층·상세위치를 실제로 제공**한다 |
| 2 | **10cm 임계 + 도어별 다이어그램** (동료 3) | 연단간격 M값 이벤트를 화면 언어로 번역한 것. "위험 구간 색칠"보다 **"3-2번 문으로 타세요"**가 훨씬 강하다 |
| 3 | **점검·보수 사전 안내** (동료 2) | 파급영향 분석을 "사후 측정"이 아니라 **"헛걸음 방지"**로 프레이밍한다. 같은 데이터인데 사용자 가치가 명확해진다 |
| 4 | **목적지 지향 경로** (동료 5) | 병원·복지관까지의 경로. **평지에서 비용면이 단색으로 나오는 문제를 우회한다** — 면은 변별력이 없어도 선(경로)은 계단·횡단보도 회피로 결과가 나온다 |
| 5 | **쾌적 지수** (동료 6) | 혼잡도 통계를 "회피 시간대 추천"이라는 사용자 언어로 바꾼 것 |

> 특히 **4번은 앞서 검증에서 나온 한계를 정확히 보완한다.**
> 5m DEM 경사면은 서울 평지에서 전 셀이 「양호」 한 등급으로 나와 지도가 단색이 된다.
> 동료의 경로 방식은 같은 데이터로 평지에서도 결과가 나온다.

## 동료 안에서 고쳐야 할 것

### 데이터 선택 오류 — 동료 6
「장애인 월별 승하차」(`OA-22478`)는 **월 단위**라 시간대 추천에 쓸 수 없다.
시간대별 교통약자 수요는 `OA-22470`(승객유형별 시간대별) 또는 `OA-22483`(노인 시간대별)이어야 한다.

### 이미 있는 실측 데이터를 안 쓰고 있음 — 동료 1
"교통약자 보행 속도 기준 맞춤 환승 시간"을 **계수로 추정**하려는 것으로 보인다.
`OA-21221`이 **일반/경로/장애인별 실측 환승시간**을 준다. 추정 대신 실측을 쓰면 훨씬 강하다.

### 데이터가 목록에 없음 — 동료 5
목적지로 든 **병원·복지관 POI가 데이터 목록에 없다.**
`서울시 장애인편의시설 목록정보`(한국사회보장정보원, 전국)로 대체하거나 별도 POI를 확보해야 한다.

## 동료 안 6개의 착수 조건 — 절반이 미확인 요소에 걸려 있다

| 동료 안 | 조건 | 실패 시 |
| --- | --- | --- |
| 1. 계단 0% 환승 | **KRiC 서비스키 필수** | 「계단 0%」 판정 자체가 불가. 다기준 경로의 나머지 기준은 키 없이 성립 |
| 2. 당일 점검현황 | **`OA-15994` 갱신주기가 실시간인가** | 「당일」이 기능의 전부다. 스냅샷이면 **기능이 성립하지 않는다** — 가장 취약 |
| 3. 도어별 연단간격 | **`OA-22124` 「승강장위치」가 도어 번호인가** | 역당 1행 대표값이면 도어별 다이어그램이 불가. 역별 등급표로 축소 |
| 4. 화장실·충전소 | 없음 | — 바로 착수 가능 |
| 5. 안심 보행로 | 없음 | — 바로 착수 가능 |
| 6. 쾌적 시간대 | 없음 (데이터 교체만) | — 바로 착수 가능 |

**하필 가장 매력적인 1·2·3이 미확인 요소에 걸려 있다.** 이 세 게이트는 기존 검증에서 식별한 것과 정확히 같다.
파일 1건씩만 열어보면 끝나므로 **아이디어를 확정하기 전에 이것부터 확인할 것.**

## 구조적 관찰 — 두 안은 성격이 다르다

- **동료 안 6개는 전부 개인 이용자용 앱 기능이다** — 지금 이동하려는 사람을 돕는다(경로·핀·필터·추천)
- **기존 12개는 공간분석 기능이다** — 도시 전체의 접근성 격차를 드러낸다(등시선·결핍지도·손실면적·대시보드)

충돌이 아니라 **같은 파이프라인의 앞뒤**다. 그리고 둘 다 필요하다.
분석만 있으면 "그래서 뭐?"가 되고, 앱만 있으면 GIS 연산이 얕아진다.

### 동료 안만으로 갈 때 빠지는 것

동료 6개에는 **래스터 GIS와 공간통계가 통째로 없다.**

| 빠지는 것 | 어디에 있었나 |
| --- | --- |
| 등고선 → DEM 보간, Horn 경사, 재분류, 지도대수 | 접근 비용면 |
| 등시선 · 버퍼 차집합 (허수 역세권) | 실측 도보 등시선 |
| 2SFCA · 존 통계 · 이변량 코로플레스 · GWR | 결핍 지도 · 행정동 대시보드 |
| 연결성 분석 · 손실 면적 산정 | EV 장애 파급영향 |
| 지오레퍼런싱 · 3D 익스트루전 | 안내도 정합 · 3D 단면 |

동료 6개의 GIS 연산 강도를 보면 **네트워크 라우팅(1·5)과 선형참조(3)만 남고,
2·4·6은 마커 표출·속성 필터·시계열 통계**다. 공간 연산이라 보기 어렵다.
이대로 가면 "GIS 프로젝트"가 아니라 **"지도를 쓰는 앱"**이 된다.

## 통합 제안 — 2층 구조

동료 안을 **화면 층**, 기존 안을 **엔진 층**으로 두면 하나의 시스템이 된다.
같은 데이터를 두 번 만들 필요가 없다.

| 엔진 (분석) | 화면 (동료 안) | 공유 자산 |
| --- | --- | --- |
| 접근 비용면 · 도보 등시선 | 5. 안심 보행로 | **경사 임피던스 그래프** 하나로 면과 선을 둘 다 |
| 다기준 경로탐색 · 실내 3D 라우팅 | 1. 계단 0% 환승 | **네트워크 그래프 + 환승 페널티** |
| EV 장애 파급영향 | 2. EV 핀 + 점검현황 | **승강기 상태 테이블** — 표출이 곧 분석의 입력 |
| 연단간격 위험도 | 3. 도어별 다이어그램 | **LineString(M) + 이벤트 테이블** |
| 결핍 지도 (2SFCA) | 4. 화장실·충전소 필터 | **시설 인벤토리 + 개찰구 내외 속성** |
| 혼잡도 핫스팟 | 6. 쾌적 시간대 추천 | **역 × 30분 혼잡 매트릭스** |
| 행정동 대시보드 · 3D 단면 · 안내도 정합 | (대응 없음 — 분석 전용) | |

**6쌍 전부 자산을 공유한다.** 엔진을 만들면 화면은 그 위에 얹히고,
화면 6개는 엔진이 만든 것을 사용자 언어로 보여준다.

### 권고

1. **엔진부터 만든다.** 화면은 엔진 없이 못 만들지만, 엔진은 화면 없이도 결과가 나온다
2. **동료의 5가지 통찰을 명세에 흡수한다** (개찰구 내/외 · 도어별 UI · 사전 안내 프레이밍 · 목적지 경로 · 쾌적 지수)
3. **동료 4·5·6은 조건이 없으니 화면 작업의 착수점으로 좋다.** 1·2·3은 게이트 확인 후
4. **행정동 대시보드 · 3D 단면 · 안내도 정합은 남겨둔다.** 이게 빠지면 GIS 프로젝트로서의 폭이 사라진다
