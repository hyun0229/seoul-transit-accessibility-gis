# 기능 12개 실현가능성 검증

검증일 2026-09-08 · 대상: `docs/기능정의_노션용.md` 의 A1–C4
근거: Notion「교통약자 관련 데이터 정리」(최종수정 09-05) 데이터 목록 + 각 데이터셋 메타 조사

## 이 검증의 한계 — 먼저 밝힘

- **원시 데이터를 한 건도 열어보지 못했다.** 작업 환경의 egress 정책이
  `data.seoul.go.kr` · `www.data.go.kr` · `data.kric.go.kr` · `t-data.seoul.go.kr` 를 전부 차단한다.
  포털 페이지 조회도, 파일 다운로드도 불가.
- Notion에 붙어 있는 `dump.zip` 도 바이너리라 받지 못했다.
- 따라서 아래 판정은 **데이터셋 메타정보(제공항목·형식·갱신주기) 수준의 근거**와
  명세 자체의 논리 정합성 검사에 기반한다. 컬럼 실값을 봐야 갈리는 항목은
  「확인 게이트」로 따로 표시했다.
- 기존 `README.md` 의 "핵심 3건 스키마 직접 확인" 은 이전 세션 결과이며 이번에 재확인하지 못했다.

## 결론 세 줄

1. **데이터가 없어서 못 만드는 기능은 없다.** 12개 전부 어떤 형태로든 성립한다.
2. **그러나 명세에 쓴 방법 그대로는 못 만드는 기능이 4개다** — A3 · B2 · B4 · C1→C2 연결.
   입력이 존재하지 않는 연산을 적어놨거나, 데이터 성격과 연산이 안 맞는다.
3. **진짜 단일 장애점은 KRiC 서비스키 하나.** C2 전부와 B1의 「계단 없는 길」 기준이 여기 걸린다.
   현재 최소 시연 조합(A1+A2+B1+B3+C1+C2)은 6개 중 2개가 이 키와 안내도 성격에 동시에 물려 있다.

## 명세대로는 안 되는 것 4건

### 1. A1 — 「보도폭」은 없는 데이터다

명세의 AHP 가중중첩 인자는 *경사 · 횡단시설 · 보도폭* 셋인데, 보도폭을 주는 데이터셋이 목록에 없다.
도보 네트워크(`OA-21208`)가 제공하는 링크 속성은 **링크 길이 · 행정구역 · 링크 유형**
(고가도로 / 지하철 / 교량 / 터널 / 육교 / 횡단보도 / 공원·녹지 / 건물내 통로)이고 **폭 속성이 없다.**

→ 인자를 교체한다: `경사 · 횡단보도 밀도 · 육교·지하보도 링크 밀도(우회 강제 지표)`.
가중중첩 구조 자체는 그대로 살아 있으므로 A1은 성립한다.

**추가 주의** — 등고선 보간 DEM 5m는 **지형 경사**다. 휠체어의 실제 장벽인 연석·단차·보도 횡단경사는
이 해상도에서 표현되지 않는다. 산출물을 "휠체어가 못 넘는 경사"로 라벨링하면 과장이 된다.
"지형 기복에 따른 통행 부담" 으로 표현하고, 미시 단차는 범위 밖임을 명시할 것.

### 2. A3 — 시설이 역 안에 있어서 「공급 연속면」이 안 만들어진다

명세는 시설 Point → KDE → 연속 공급 래스터를 상정한다. 그런데 목록의 시설 데이터
(장애인화장실 · 수어영상전화기 · 교통약자 도우미 · 휠체어 급속충전기 · 음성유도기 일부)는
**대부분 지하철 역사 내부 시설**이다. 이걸 KDE로 밀면 결과는 시설 분포도가 아니라
**역 위치의 KDE**가 된다 — 즉 "역이 있는 곳에 시설이 있다"는 동어반복.

→ 공급 단위를 셀이 아니라 **역**으로 두고, A2 등시선을 캐치먼트로 삼아
**역 단위 2SFCA**를 수행한다. 2SFCA는 원래 시설-수요 쌍 기반이라 이 구조가 오히려 정석이다.
연속 공급면 KDE는 버린다. (단 음성유도기·횡단보도처럼 가로에 흩어진 시설은 KDE가 유효하므로
가로시설 / 역내시설을 분리해 다룰 것.)

### 3. B2 — 혼잡도는 시계열이 아니다

`OA-12928`(1~8호선) · `OA-22197`(9호선)이 주는 것은 **요일·방향별 30분 단위 평균 혼잡도** =
대표일 프로파일이다. 날짜축이 없다.

- **Mann-Kendall 추세 분석은 이 파일 하나로는 불가능하다.** 시간축이 "하루 중 시각"이지
  "연도/날짜"가 아니다. 추세를 보려면 **연도별 파일을 여러 개 받아 쌓아야** 하고, 그건 별개 작업이다.
- (x, y, t) 3D 래스터 크리깅은 과잉이다. 역은 노선 축 위 1차원 사슬이고 간격은 ~1km다.
  이 배치에 공간보간을 걸어봐야 새 정보가 거의 생기지 않는다. 장식적 연산이다.
- Getis-Ord / Moran's I 는 유효하지만 **유클리드 가중치가 아니라 네트워크 인접 가중치**여야 한다.
  명세에 이 구분이 없다.

→ B2를 「역 단위 시간대 프로파일 + 네트워크 가중 핫스팟 + (연도 파일 확보 시) 추세」로 축소하면 견고하다.

### 4. B4 — 열차 좌표가 없다

실시간 열차 위치 API가 주는 것은 `statnId` / `statnNm` / `trainSttus`(진입·도착·출발·전역출발) 수준의
**역 기준 상태값**이지 위·경도가 아니다. 따라서 명세의

> `V` 맵 매칭 — 열차 좌표를 노선 LineString에 투영 (`ST_ClosestPoint`)

는 **입력이 없어서 성립하지 않는다.** 투영할 좌표가 애초에 없다.

→ 실제로 하게 되는 일은 **역 이벤트 → 노선 선형참조 보간**이다
(현재역 M값과 다음역 M값 사이를 `trainSttus` 로 0 / 0.5 / 1 배분). 이것도 선형참조 연산이므로
GIS 연산 카탈로그에서 잃는 건 "맵 매칭" 한 줄뿐이다. 명세를 정정할 것.

한편 알림정보(`OA-22718`)는 Notion에 본인이 적어둔 대로 형식이 없어 파싱이 어렵다.
LLM 구조화는 가능하지만 신뢰도가 낮으므로 **데모 보조**로만 두고 정량 지표에는 넣지 말 것.

## C1 · C2 — 여기가 제일 위험한데, 뒤집으면 안전해진다

### 지금 명세의 구조가 위험한 이유

명세는 `C1 지오레퍼런싱 → 그 도면 위에 디지타이징 → C2 실내 네트워크` 순서다.
즉 **C2의 기하가 C1의 정합 품질에 통째로 의존**한다.

그런데 서울교통공사 역이용안내도는 승객 안내용 **JPG 이미지**이고, 이런 도면은 통상
축척이 균일하지 않은 **모식도**다(통로 과장, 계단 심볼화, 비율 왜곡). 모식도라면:

- Affine / 2차 다항식 변환의 RMSE가 크게 나온다.
- TPS 러버시팅으로 억지로 맞출 수는 있으나, **그 위에서 디지타이징한 통로의 길이·거리는
  물리적 의미가 없다.** C2가 그 길이로 비용을 계산하면 결과 전체가 허구가 된다.

Notion 원문에도 본인이 이미 이렇게 적어놨다 —
*"역이용안내도를 활용해 여기에서 보이는 이미지를 연결해 소개해주는게 최대일 것 같습니다."*
이 판단이 명세보다 현실에 가깝다.

### 뒤집으면 되는 이유 — C2는 C1 없이도 성립한다

KRiC 이동동선 API는 좌표를 주지 않는 대신 **위상 + 실거리 + 층**을 준다:
`stMovePath` → `edMovePath` + 순서(위상), `mvDst`(구간 거리), `stinFlor`(층),
`elvtTpCd`/`elvtSttCd`(승강기 유형·상태).

이건 **기하 없는 node-relation graph** 그 자체다. 여기에
`OA-12514`(EV·ES 길이·높이, 2026-04 갱신)로 수직 비용을 실측값으로 채우면,
계단 = ∞ 제약 최단경로가 **좌표 한 개 없이 완전히 돌아간다.**

→ **설계 반전:**
- C2의 그래프와 비용은 **KRiC 위상 + `mvDst` + `OA-12514` 높이**에서 나온다.
- C1의 정합 도면은 **표출용 배경**으로만 쓴다. 모식도여도 무방하다.
- C1의 산출물 주장을 "실내 벡터 생산의 기반"에서 "지도 위 정합 오버레이 + RMSE 정직 보고"로 낮춘다.
  모식도에서 RMSE가 크게 나오는 것을 그대로 보고하는 것은 오히려 방법론적으로 정직한 결과다.

이렇게 하면 안내도가 모식도로 판명나도 **C2가 무너지지 않는다.** 지금 구조에서는 같이 무너진다.

### GCP 후보 — Notion 목록에 없는 데이터셋 하나

`OA-21212` **서울시 지하철역 엘리베이터 위치정보** 는 **WGS84 위·경도**를 준다.
Notion 목록의 `OA-22725`(편의시설위치정보 엘리베이터)는 설치위치·운영여부를 텍스트로 주는 것이라
좌표가 없을 가능성이 높다. C1의 GCP와 B3의 승강기 공간 배치 모두 `OA-21212` 쪽이 맞다.
**목록에 추가할 것.**

## 확인 게이트 3건 — 착수 전에 반드시 눈으로 볼 것

각각 실패하면 해당 기능의 산출물 형태가 바뀐다. 셋 다 이번 세션에서는 접근 차단으로 확인하지 못했다.

### 게이트 1. 역이용안내도 1장 (C1 · C2)
축척 도면인가 모식도인가. `OA-11984` 에서 아무 역 1장을 받아 눈으로 본다.
- 모식도면 → 위의 「설계 반전」을 적용한다. C1은 시각화 전용으로 강등.
- 축척 도면이면 → 현재 명세대로 진행 가능. 디지타이징 기하가 살아난다.

### 게이트 2. 승강기 가동현황 `OA-15994` 갱신주기 (B3)
「정상 가동 여부」를 주는 것은 확인됐으나 **실시간인지 일/월 단위 스냅샷인지 미확인**이다.
- 실시간이면 → 명세대로 "오늘 못 가는 역" 성립.
- 스냅샷이면 → B3를 **what-if 시뮬레이터**로 프레이밍 변경
  ("○○역 EV가 멈추면 1.4km²가 사라진다"). 데모 임팩트는 거의 그대로다.

### 게이트 3. `OA-22124` 「승강장위치」 컬럼 값 형식 (C3)
제공항목은 `호선 · 역외부코드 · 역코드 · 역명 · 상하선 · 승강장위치 · 연단간격 · 높이차` 로 확인됐다.
관건은 승강장위치가 `1-1` `3-4` 같은 **차량-도어 번호**인지 여부.
- 차량-도어 번호면 → M값 이벤트가 그대로 꽂힌다. C3 완전 성립, 동적 분할이 진짜로 작동한다.
- 역당 1행 대표값이면 → 분할할 대상이 없어져 C3는 **역별 위험 등급표**로 축소된다.

**부수 사항** — 어느 쪽이든 **승강장 LineString(M) 기하 자체는 주어지지 않는다.**
역 좌표 + 승강장 형식(`OA-22452`) + 역사 길이(`OA-11572`)로 **합성**해야 한다.
합성 기하임을 산출물에 명시할 것. 실측 위치가 아니다.

**추가 수확** — `OA-22124` 는 `역외부코드` 와 `역코드` 를 **함께** 준다.
착수 전 결정사항의 「역 코드 매핑 테이블」을 만들 때 이 데이터셋이 브릿지로 쓸 만하다.

## A2 · B3 의 공통 약점 — 계단이 없다

도보 네트워크에 **계단 속성이 없다.** 링크 유형으로 육교·지하보도·건물내 통로는 구분되지만,
서울 구릉지 주택가의 **계단길**은 일반 보도 링크와 구분되지 않는다.

이건 A2 등시선의 정확도를 직접 결정하고, **B3의 손실 면적 km² 가 A2 등시선의 차집합이므로
그 오차를 그대로 상속한다.** 발표에서 가장 강한 숫자가 가장 약한 가정 위에 서 있다.

→ 실무적 해법: **DEM 링크 경사를 계단의 대리 변수로 쓴다.** 계단길은 대부분 급경사 구간에
놓이므로, 링크 평균 경사가 임계값(예: 15%)을 넘으면 휠체어 통행 불가로 처리한다.
A1의 DEM이 이미 있으므로 추가 데이터가 필요 없고, 논리도 방어 가능하다.
**단 이 대리 처리를 문서와 발표에 명시해야 한다.** 숨기면 질문 한 번에 무너진다.

## 최소 시연 조합 재검토

현재 조합 **A1 + A2 + B1 + B3 + C1 + C2** 는 6개 중 **2개(C1 · C2)가
KRiC 서비스키와 안내도 성격이라는 외부 미확인 요인에 동시에 걸려 있다.**
키 승인이 늦어지거나 안내도가 모식도면 시연 서사의 3분의 1이 멈춘다.

**대안 조합 — 외부 승인 의존 0:**

> **A1 + A2 + B1 + B3 + C3 + C4**

- 래스터: DEM 보간 · Horn 경사 · 재분류 · 지도대수 · 비용거리 · 존통계 (A1)
- 벡터 네트워크: 위상 구축 · 임피던스 · 등시선 · 차집합 (A2)
- 그래프: 시간의존 최단경로 · 다기준 (B1)
- 동적 그래프 + 시뮬레이션 + 면적 산정 (B3)
- 선형참조 · 동적 분할 (C3)
- 3D 익스트루전 · DEM 샘플링 (C4)

GIS 스펙트럼(래스터 분석 · 네트워크 · 선형참조 · 3D)이 전부 덮이고,
**전부 파일/공개 API로만 확보 가능하다.**
KRiC 키가 나오면 C2를 얹어 실내 3D까지 확장한다 — 키를 기다리며 멈추지 않는 구조.

## 착수 전 할 일 (순서대로)

1. **KRiC 서비스키 신청을 오늘 시작한다.** 19건 개별 신청이고 승인에 시간이 걸린다.
   우선순위는 `docs/kric_api_inventory.md` 의 순서대로. 이게 임계경로다.
2. **게이트 3건 확인** — 안내도 1장 · `OA-15994` 갱신주기 · `OA-22124` 승강장위치 형식.
   셋 다 파일 1개씩만 받아보면 끝난다.
3. **역 코드 매핑 테이블 작성.** `station_master` 기준, `OA-22124` 의 역외부코드/역코드 쌍을 브릿지로.
   조인 키는 역명+호선, 역사마스터 위·경도로 교차검증.
4. **좌표계 고정** — 분석 `EPSG:5179`, 표출 `4326/3857`. 나중에 고치면 A1·A2가 통째로 어긋난다.
5. 명세 정정 — 위 4건(A1 보도폭 / A3 공급면 / B2 큐브 / B4 맵매칭)과 C1↔C2 의존 반전.
