# 교통약자 지하철 접근성 GIS — 요약

서울 지하철을 **교통약자 기준으로 다시 그리는** 웹 GIS.
역 밖(지형·보행) → 노선(환승·혼잡) → 역사 안(층·승강장) 세 스케일을 하나의 좌표계로 잇는다.

**기능 12개 · 벡터 12 / 래스터 9 · GIS 연산 32종**
원 문서 데이터 링크 56개 전수 검증 완료 — **영구적으로 죽은 링크 0건**

---

## 왜 GIS인가

**래스터가 필요한 이유** — 경사·밀도·통행비용은 점이 아니라 **연속된 면**이다. 이웃연산(3×3 경사), 지도대수(여러 표면 합치기), 비용거리는 래스터 GIS 외에 대체 수단이 없다. 게다가 서울시는 **경사도 래스터를 주지 않고 등고선·표고점만** 주기 때문에 DEM을 직접 만들어야만 한다.

**벡터가 필요한 이유** — 지하철은 좌표를 가진 **위상 그래프**다. 계단 비용을 ∞로 두는 순간 일반 길찾기가 교통약자 라우팅이 되고, 노드에 층(level) 속성이 붙으면 2D로는 못 푸는 **실내 3D 문제**가 된다.

**둘이 만나는 지점** — 도보 링크마다 DEM을 샘플링해 경사 임피던스를 만들고(벡터←래스터), 벡터 등시선을 지워가며 래스터로 누적한다(래스터←벡터).

## 이 프로젝트의 승부처

**"역사 내부 shp 파일이 없다"를 정면으로 푼다.** 역 이용안내도 이미지를 지오레퍼런싱해(C1) 그 위에 실내 통로를 직접 디지타이징하면(C2), 데이터가 없어서 못 하던 실내 라우팅이 가능해진다. 전 역을 다 할 필요 없이 **환승 대역 5~10개 역**이면 시연으로 충분하고, "데이터를 직접 생산했다"는 점이 평가에서 가장 강한 카드가 된다.

**가장 임팩트 있는 데모는 B3.** "오늘 ○○역 엘리베이터가 멈춰서 휠체어 이용자 기준 도시 면적 1.4km²가 사라졌습니다" — 이게 지도와 숫자로 동시에 나온다.

## 착수 전 반드시 정할 것

1. **좌표계** — 서울시 데이터는 `EPSG:5174 / 5179 / 5186`이 섞여 온다. 면적·거리·경사는 **투영좌표 5179**에서, 웹 표출만 `4326`. 나중에 고치면 A1·A2가 통째로 어긋난다.
2. **역 코드 매핑** — KRiC의 `stinCd`와 서울시의 `stnCd` / `stop_id` 체계가 다르다. `station_master`를 기준으로 매핑 테이블을 먼저 만들어야 S2와 S3가 연결된다.
3. **혼잡도 출처 단일화** — 서울 공공 혼잡도와 SK Open API는 측정 기준이 다를 수 있다. 하나만 쓰고 출처를 명시한다.

## 데이터 관련 주의

- **생활이동 데이터는 내국인 / 외국인 분할**이다. 문서의 "연령·목적별 / 교통수단별" 구분은 사실과 다르며, **수단별 분석을 하면 외국인 데이터를 쓰게 된다** (A4 설계 영향).
- **T-DATA는 서버가 불안정**하다. 같은 URL이 성공과 실패를 오가므로 수집 스크립트에 재시도를 넣는다.
- **KRiC 교통약자 API는 19건**(문서엔 6건). 다만 대부분 2020년에 갱신이 멈춰 있어, 겹치는 항목은 공공데이터포털 2026년 최신본을 우선한다.
