# 교통약자 지하철 접근성 GIS

서울 지하철을 교통약자 기준으로 다시 그리는 웹 GIS 프로젝트.
역 밖(지형·보행) → 노선(환승·혼잡) → 역사 안(층·승강장) 세 스케일을 하나의 좌표계로 잇는다.

기능 12개 · 벡터 12 / 래스터 9 · GIS 연산 32종.

## 진행 상황

원 자료(Notion「교통약자 관련 데이터 정리」)의 데이터 링크 56개를 전수 검증했다.
**영구적으로 죽은 링크는 0건.** 이후 핵심 3건은 스키마까지 직접 확인했다.

### 확인 완료

- **도보 네트워크** — 노드/링크 WKT 제공. 위상이 이미 구축된 네트워크라 A2의 부담이 크게 준다.
  육교·횡단보도·건물내 플래그 있음. 명시적 "계단" 컬럼은 없어 육교 플래그로 근사해야 한다.
- **KRiC 이동동선 API** — **좌표 필드가 없다.** 위상(`stMovePath`→`edMovePath`+순서),
  거리(`mvDst`), 승강기 유형·상태(`elvtTpCd`/`elvtSttCd`), 층(`stinFlor`), 이미지(`imgPath`)만 준다.
  C2는 재설계했고, B3는 좌표가 필요 없어 무사하다.
- **역 코드 체계** — 서울시 역사마스터는 TOPIS 블록 코드(`0xxx` 1~4호선 · `2xxx` 5호선 ·
  `4xxx` 9호선 · `9xxx` GTX). KRiC `stinCd`와 직접 파생 규칙은 없다.
  조인 키는 **역명 + 호선**, 역사마스터의 위·경도로 교차검증한다.
- **서울시 경사도** — 경사도 래스터가 아니라 **등고선 + 표고점 shp만** 제공.
  DEM 직접 생성이 필수 공정으로 확정됐다.

### 남은 확인

1. **역 이용안내도 1장** — 축척 도면인지 모식도인지. 모식도면 C1이 무너지고 C2의 지도 경로도 같이 무너진다.
2. **KRiC `stMovePath` 실제 값** — 사람이 읽는 명칭인지 코드인지. C2 공수를 두 배 가른다.
   서비스키가 있어야 확인 가능. 로그인은 `www.kric.go.kr/jsp/general/lgn/login.jsp`
   (`openapi.kric.go.kr`이 아니다).

## 착수 전 결정사항

- **좌표계** — 서울시 데이터는 `EPSG:5174 / 5179 / 5186`이 섞여 온다.
  면적·거리·경사 연산은 투영좌표 `5179`에서, 웹 표출만 `4326 / 3857`.
- **역 코드 매핑 테이블** — 이걸 먼저 만들지 않으면 S1·S2·S3가 서로 연결되지 않는다.
- **혼잡도 출처 단일화** — 서울 공공 혼잡도와 SK Open API는 측정 기준이 다를 수 있다.

## 최소 시연 조합

**A1 + A2 + B1 + B3 + C1 + C2** — "래스터 지형분석 → 벡터 네트워크 → 실내 → 실시간 반영" 서사가 완결된다.
혼자 진행한다면 **A1 + A2 + B3 + C3** 네 개로 줄여도 GIS 스펙트럼은 다 보여준다.
